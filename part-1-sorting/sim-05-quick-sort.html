Welcome - Start Here

Quick Sort is one of the fastest sorts in practice. This lab shows Lomuto partitioning: pick a pivot (red), scan with j (yellow), and track boundary i (purple). No coding needed - use Run and Step like the other simulations.

What You See on Screen
  • Chart: Bars change colour during partition and recursion.
  • Depth counter: Shows recursion depth (how “deep” the algorithm is).
  • Controls: Same layout as Sims 1–4.
  • Info panel: Scroll down on mobile to read “Properties”, “Best Used When”, and the complexity grid at the bottom.
Your First Run
  1. Use Size 12–20 and click Run ▶.
  2. Watch the red pivot and how values smaller than it move to the left.
  3. Try Order → Reversed to see more work (worst-case behaviour with a simple pivot).
  4. Use Step after Pause to follow one comparison at a time.
Controls Explained
  • Size / Speed: Bar count and animation rate.
  • Order / Custom / New: Change input data (custom: 50, 12, 33, 7 + ✓).
  • ☰ menu: Return to lab home or open Merge Sort (previous sim).
  • AI tab: Ask about pivot, Lomuto, or vs merge sort.
Colour Legend (Quick Sort)
  • Blue - not yet in final partition position
  • Red - pivot element
  • Purple - Lomuto index i (end of “small” region)
  • Yellow - scan index j
  • Green - sorted / placed

How Quick Sort Works

Quick Sort chooses a pivot, partitions the array so smaller values sit left and larger values sit right, then repeats on each side. This demo uses Lomuto partitioning. Average time is O(n log n); worst case O(n²) on bad pivots (e.g. sorted array with naive pivot).

Complexity
BestO(n log n)
AverageO(n log n)
WorstO(n²)
SpaceO(log n)
Properties

❌ Not stable   ✅ In-place   ✅ Cache-friendly (fastest general purpose sort)

Best Used When

Default sorting algorithm in most systems (V8, standard libraries) because its tight inner loop makes it extremely fast in practice, despite the rare O(n²) worst-case on already-sorted arrays (if naïve pivot is chosen).
